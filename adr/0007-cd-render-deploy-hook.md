# ADR-0007: CD на stage через Render і deploy hook із GitHub Actions

- Статус: прийнято
- Дата: 2026-11-25
- Автор рішення: Науменко Анна

## Контекст і проблема

CI вже перевіряє кожен PR, а мердж у `main` заблоковано без зеленого `ci-ok` (ADR-0005). Потрібен CD: коміт у `main` автоматично розгортається на stage, сервіс доступний з інтернету. Межі завдання ті самі, що в ADR-0006: раннер CI не має доступу до БД і SSH на машину немає, тому міграції виконує контейнер під час старту.

## Фактори вибору

- деплой запускається лише після зеленого CI;
- немає SSH і доступу CI до машини;
- не потрібна банківська картка;
- можна довести, що на stage працює саме той коміт, який змерджено;
- конфігурація CD лежить у репозиторії, а не лише в панелі хостингу.

## Розглянуті варіанти

- A. Render (безкоштовний Docker-сервіс) і deploy hook, який викликає workflow GitHub Actions.
- B. Вбудований Auto-Deploy Render («After CI Checks Pass»).
- C. Віртуальна машина із SSH.
- D. Інший PaaS (наприклад, Fly.io).

## Рішення

Обрано A. Workflow `.github/workflows/cd.yml` запускається після успішного CI на пуші в `main`, викликає deploy hook Render з SHA цього коміту, чекає, поки `GET /version` поверне цей SHA, і перевіряє `GET /health`. Автодеплой у самому Render вимкнено, щоб деплой ішов лише через workflow. Секрет `RENDER_DEPLOY_HOOK_URL` і адреса stage `STAGE_URL` лежать у налаштуваннях репозиторію.

### Плюси й мінуси варіантів

**A. Render і deploy hook**

- Плюс: не потрібні картка й SSH; деплой запускається лише після зеленого CI; збіг SHA на stage перевіряється автоматично; CD видно в репозиторії.
- Мінус: безкоштовний інстанс засинає після 15 хвилин без запитів, перший запит після цього повільний.
- Мінус: файлова система тимчасова, SQLite скидається при кожному деплої, тому на stage задано `SEED=true`.

**B. Вбудований Auto-Deploy Render**

- Плюс: найпростіше, нічого писати.
- Мінус: налаштування лише в панелі; збіг SHA ніхто не перевіряє.

**C. Віртуальна машина із SSH**

- Плюс: повний контроль і постійний диск.
- Мінус: суперечить межам з ADR-0006 (CI без SSH); потрібно підтримувати сервер.

**D. Інший PaaS**

- Плюс: бувають постійні томи.
- Мінус: потрібна банківська картка.

## Наслідки

- Stage придатний для демонстрації й перевірки, але не зберігає дані між деплоями.
- Відкат виконується вручну з панелі Render до одного з попередніх деплоїв.
- Для prod знадобиться платний інстанс із постійним диском.
