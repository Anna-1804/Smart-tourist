## 4. Висновки

1. **Покриття гілок не гарантує якість перевірок.** Усі 8 перших прогалин були в коді зі 100% покриттям гілок: код виконувався, але його результат (текст помилки, рядок журналу) ніхто не перевіряв.
2. **Журнал запиту був найслабшим місцем** (`requestContext.js`, 68,42%). Після виправлення модуль має 100%.
3. **Мутаційний звіт виявив втрачений тест.** Після злиття гілок тест журналу запиту зник через конфлікт, а мутанти `requestContext.js` знову вижили, що й показало втрату. Без мутаційного звіту це залишилося б непоміченим.
4. **Новий код потребує повторного прогону.** Валідація, додана під час виправлення дефектів, дала 8 нових прогалин: перший набір тестів виправлення перевіряв основні випадки, але не нетипові типи значень (`undefined`, число, `null`) і пробіли.
5. **Решта 7 мутантів не потребує дій.** Вони або еквівалентні, або стосуються тексту діагностичних записів.
6. **Обмеження.** `coverageAnalysis: off` означає, що кожен мутант проганяє весь набір тестів (прогін ~25 хвилин). Область не охоплює `repositories/` і `database/`: там логіка залежить від SQLite і перевіряється інтеграційними тестами.
