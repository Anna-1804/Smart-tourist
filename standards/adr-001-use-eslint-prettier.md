1. Завдання проєкту
Розробка вебплатформи «Smart Tourist» із наступним функціоналом:

Для користувачів: Перегляд туристичних маршрутів (назва, фотографії, ціна, детальний опис, інтерактивна карта з точками та відгуки з оцінками).

Для адміністратора: Зручне додавання нових маршрутів, завантаження фотографій та редагування наявної інформації.

2. Архітектурний підхід
Обрано класичну клієнт-серверну модель із серверним рендерингом (Server-Side Rendering — SSR) без використання складних фронтенд-фреймворків (типу React):
1. Клієнт (Браузер): надсилає звичайні HTTP-запити на сервер і відображає отримані HTML-сторінки та стилі.
2. Сервер (Node.js/Express): приймає запити від клієнта, виконує бізнес-логіку, працює з базою даних SQLite, вставляє дані у шаблони EJS та віддає клієнту готові HTML-сторінки.

3.Стек технологій
- Сервер (Backend): Node.js + Express — обробка запитів клієнта, бізнес-логіка та адмін-панель.
- Шаблонізатор (Views): EJS — формування HTML-сторінок на стороні сервера перед відправкою клієнту.
- Інтерфейс клієнта (UI): HTML5 + Bootstrap 5 (CSS) — безкоштовна бібліотека стилів для швидкої верстки форм, картки турів та кнопок адмінки.
- База даних (Database): SQLite — зберігання даних про маршрути, фотографії та відгуки.

4. Чому саме цей стек
- Простота: Реалізація клієнт-серверної архітектури через Express + EJS не вимагає розробки двох окремих проєктів (API + React) та складного збирання фронтенду.
- Швидкість розробки: Bootstrap надає готові елементи інтерфейсу, а PostgreSQL надійно зберігає зв'язки між даними.

5. Наслідки
- Позитивні: Проста, зрозуміла та надійна клієнт-серверна система в єдиному репозиторії; легка підтримка лінтерами (ESLint/Prettier).
- Негативні: При кожному переході між сторінками браузер завантажує сторінку з сервера заново (класична поведінка веб-сайтів).
